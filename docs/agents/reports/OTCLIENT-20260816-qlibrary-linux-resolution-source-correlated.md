## Source-correlated algorithm

For a non-plugin QLibrary load with empty `fullVersion` on generic Linux:

1. generic prefix is `lib`;
2. generic suffix list contains `.so`;
3. because the input is absolute, Qt prepends an empty prefix and empty suffix so the exact input name is tried before generic decoration;
4. on x86 + glibc with runtime `ArchHaswell` true, each prefix is expanded to a `glibc-hwcaps/x86-64-v3/` variant followed by the original prefix;
5. Qt iterates prefixes outermost and suffixes innermost;
6. it skips adding a non-empty suffix only when the input name already ends with that suffix;
7. it constructs an attempt from `path + prefix + name + suffix` and calls `dlopen`;
8. for an absolute filename, a failed `dlopen` on an attempt that **exists on disk** sets `retry=false`, so subsequent generated names are not attempted;
9. any successful `dlopen` also terminates iteration.

Therefore the deterministic ordered list below is a **potential candidate order**, not a claim that every candidate reaches `dlopen` in a real run.

## Potential candidate order — `ArchHaswell == false`

For symbolic absolute input `<APPDIR>/BattlEye/BEClient`:


`<APPDIR>/BattlEye/BEClient.so` is therefore generated as potential candidate index `1` in this branch.

## Actual-attempt semantics

The actual runtime attempt sequence is a prefix of the applicable potential-candidate list:

- it ends immediately at the first successful `dlopen`; or
- for this absolute input, it also ends after the first failed `dlopen` whose attempted path exists according to `QFile::exists`; or
- it consumes the entire potential list only if every attempt fails and none of the failed absolute paths exists at the post-`dlopen` check.

Consequently, source correlation proves that `BEClient.so` is generated by Qt 6.9.3 in both CPU branches, but it does **not** prove that `BEClient.so` is actually attempted in a given runtime. For example, if the earlier extensionless candidate exists but cannot be loaded, Qt stops after that failed attempt and never reaches the later `.so` candidate.

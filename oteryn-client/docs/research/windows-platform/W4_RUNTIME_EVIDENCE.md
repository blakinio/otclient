## 1. Scope

This report records what the bounded W4 blank-window application-shell spike actually proves. It does not claim renderer, GPU, protocol, identity, asset, audio, feature-UI, persistence, updater, minimum-Windows, hardware or performance compatibility.

The package contains:

- a deterministic shell state machine independent of native handles;
- one main-thread `winit::ApplicationHandler`;
- one resizable blank window created after `resumed`;
- explicit close, destroyed, focus, resize/minimize/restore, scale-factor, keyboard, modifier, mouse, cursor, wheel, IME and redraw event handling boundaries;
- one named one-shot `EventLoopProxy` wake thread joined after `run_app` returns;
- bounded structured lifecycle diagnostics using merged foundation/diagnostics contracts.

## 5. Shutdown contract proven by code/tests

The accepted shell contract is:

1. `ShellState` starts in `Starting` with a typed process generation.
2. The main-thread adapter creates at most one window after `resumed` and marks the state `Running`.
3. close/destroy or internal failure requests one idempotent transition to `Closing`.
4. transient modifier and IME state is cleared at close/focus loss.
5. the event loop exits through `ActiveEventLoop::exit`.
6. `exiting` completes `Closing -> Exited`.
7. the single named wake thread is joined after `run_app` returns.
8. no executor, scheduler, polling loop, service thread or global application registry survives shutdown.

## 6. Follow-up gate

A future package may use this shell only after revalidating live Git and exact public contracts. Renderer-surface ownership, interactive DPI/IME behavior and minimum Windows support remain separate evidence tasks. W4 does not authorize them.
